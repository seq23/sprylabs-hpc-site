## Incident summary

The 2026-07-04 BHPC agent run contained actionable recommendations in the source artifacts, but prior ingestion allowed some recommendations and new-page opportunities to disappear from normalized/apply outputs. The local updater then failed on v4 because two new validation commands were added to `package.json` but were not admitted in the validation registry/matrix.

## Root cause fixed in v5

1. **Validation registry gap fixed**
   - Added registry admission for `npm run validate:bhpc-agent-source-coverage`.
   - Added registry admission for `npm run validate:bhpc-agent-recommendation-driven-output`.
   - Added matching `_repo_validation_matrix.json` records.

2. **Agent recommendation coverage made permanent**
   - `validate:agent-run` now includes source coverage and recommendation-driven output validation.
   - Every source record must be normalized and addressed by page-level proof, queued output, or explicit skip/block reason.
   - Every required recommendation must drive visible output through an `agent_directive` block.

3. **Nested / typo / duplicate handling**
   - Nested `fix_recommendation` objects are preserved and converted into implementation directives.
   - Fuzzy route resolution handles misspelled known titles/routes, blocks ambiguity, and does not steal explicit new-page specs.
   - Source records remain individually preserved; canonical public pages are deduped.

4. **New-page handling**
   - New-page source records are counted separately from canonical page targets.
   - Current 7/4 coverage report: `10` new-page source records, `5` canonical page targets, `5` built pages, `5` queued records, `0` missing built pages.

5. **Prepush failure fixed**
   - The exact failed gate from local updater was `validate:validation-registry`.
   - v5 result: `[validate:validation-registry] OK: 119 records, 118 matrix entries, all governed commands and workflows admitted`.
