The constraints that change the answer

The useful answer changes when the operating environment changes. For this topic, the following constraints are part of the decision rather than edge cases.

  • Constraint #3: the system must still work after an interrupted or low-energy day.
  • Constraint #1: progress has to be visible as a completed action, not a feeling of preparedness.
  • Constraint #7: the rule cannot depend on adding another recurring meeting or another app to maintain.

Failure modes to diagnose before adding another tactic

  • setting a floor so high that bad days become zeros
  • using shame as a recovery mechanism
  • treating one miss as permission to renegotiate the whole plan

The tradeoff is deliberate constraint. A tighter operating rule can feel less flexible in the moment, but it prevents repeated re-deciding. For a parent, flexibility should live in the size of the action, not in whether the commitment still exists.

A realistic parent scenario

A parent loses the planned morning block to a sick child. The day does not become a write-off. The system collapses to the minimum viable commitments, moves nonessential work, and protects one meaningful action that can still be completed around caregiving.

The point of the example is not to copy the exact schedule. It is to show how the rule survives contact with a real constraint instead of requiring a perfect day.

What should a parent measure first?
