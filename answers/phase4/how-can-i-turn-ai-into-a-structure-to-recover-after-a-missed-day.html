No Catch-Up Closure Rule — recover after a missed day (0115)

The day after a miss is spent either doing double or doing nothing, and both outcomes make the day after that harder.

A miss carries no real deadline forward, only guilt, and guilt is answered either by over-correction or by avoidance. Neither is a plan.

Do this first. Log the miss in one line with no explanation, do not schedule any catch-up, and run the normal-size version of the action today at a fixed time.

Do not do this. Doubling up. It makes the return day the hardest day of the week, which attaches a cost to returning.

This level fits when: answers keep coming back plausible and unusable, which is the signature of an unbounded request. It does not fit when: you are exploring and do not yet know what good looks like. Constraints applied to exploration close it early.

When this framework is the right one. Use it when yesterday's undone list is about to be added on top of today's list.

  1. Put yesterday's undone items in a separate place from today's plan. Never merge the two lists.
  2. Give every carried item one of three dispositions: do today as a named block, reschedule to a named day, or drop.
  3. Write the dropped items down as dropped. A deletion you can see is closure; a deletion you cannot see comes back as pressure.
  4. Build today's plan only after the carried list is empty of undecided items.

Worked example: Recover after a missed day while converting an open-ended tool into a bounded one

Someone sits down with this on the list. The day after a miss is spent either doing double or doing nothing, and both outcomes make the day after that harder.

Write the form constraint first: say exactly what shape the answer must take before you describe the problem. Log the miss in one line with no explanation, do not schedule any catch-up, and run the normal-size version of the action today at a fixed time.

The framework then runs in order. First: put yesterday's undone items in a separate place from today's plan. Never merge the two lists.

Then: give every carried item one of three dispositions: do today as a named block, reschedule to a named day, or drop.

What to measure. Count how often two misses land consecutively. That number is the only one that matters here; the total count of misses is not the problem.

Running No Catch-Up Closure Rule for converting an open-ended tool into a bounded one

Undone work does not carry a deadline forward with it; it carries guilt forward. A carried list makes today structurally impossible, which produces another carried list. The rule forces an explicit disposition for every carried item so that today's list is a list someone could actually finish.

The full set of failure modes for this framework, the evidence to record, and a prompt you can paste are on its framework page. This page covers the part specific to converting an open-ended tool into a bounded one.

What this is not. It is not a productivity trick for getting more done. It usually results in less being done and more being finished.

The problem is not capability, it is that the tool will do anything, and anything is a bad default when you are trying to decide one thing.

Setup cost: the work of writing down constraints you have been holding implicitly.

Where it is strong: a bounded tool gives comparable answers across days, which is the precondition for noticing that something changed.

Where it is weak: constraints written too tightly produce answers that are technically compliant and useless.
