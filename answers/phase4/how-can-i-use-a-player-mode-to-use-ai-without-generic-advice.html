This level fits when: you want the same standard applied across sessions and you are willing to re-seed it. It does not fit when: the task genuinely needs a different standard. Forcing one mode onto everything is how modes stop meaning anything.

When this framework is the right one. Use it when you already know most of what you need to know and the problem is that it is not organized into a decision.

  1. State the decision that is actually waiting, in one sentence ending in a verb.
  2. List only what you already know that bears on it. New research is out of scope for the session.
  3. Separate the list into facts, assumptions, and unknowns, and mark which unknowns would actually change the decision.
  4. Make the decision, or name the single piece of information that would settle it and how you will get it.

Running Executive Review Mode for running the system's high-standard operating mode

When a situation is unclear, the reflex is to gather more input, and more input makes an already-unstructured picture harder to act on. Review mode forbids new material and forces the existing material into a shape a decision can be made from.

The full set of failure modes for this framework, the evidence to record, and a prompt you can paste are on its framework page. This page covers the part specific to running the system's high-standard operating mode.

What this is not. It is not strategy generation and it will not tell you something you did not already know. It converts what you know into a decision.

You are invoking a named mode with a fixed standard rather than asking an open question. The mode decides what counts as an acceptable answer.

Setup cost: knowing the mode's rules well enough to notice when it has stopped following them.

Where it is strong: a named mode is checkable. You can tell when it has drifted, which you cannot with an unnamed style.

Where it is weak: modes drift silently as a thread lengthens, and drift is easy to miss because each step is small.
