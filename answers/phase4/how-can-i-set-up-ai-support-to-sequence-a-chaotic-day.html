No Mid-Day Renegotiation Rule — sequence a chaotic day

The day contains real obligations at unpredictable times, and every plan built for it collapses before mid-morning.

The plan was written against waking hours rather than workable hours, so it was arithmetically impossible before the day started.

Do this first. List fixed constraints first, subtract them and a transition margin from the waking hours, and allocate outputs only against what remains.

Do not do this. Planning in more detail. A more detailed impossible plan is still impossible and takes longer to write.

This level fits when: the behavior you want is stable and you want it by default. It does not fit when: you are still working out what you want. Configuring an unsettled preference makes it harder to change.

When this framework is the right one. Use it on any day where the plan was made in the morning and the urge to rewrite it arrives in the afternoon.

  1. Fix the plan in the morning and treat it as closed to changes from that point.
  2. When the urge to rewrite arrives, write the proposed change down instead of making it.
  3. Finish the current block anyway. The urge usually arrives at the hardest point of the block, not at a neutral moment.
  4. Review the written proposals at the end of the day and let tomorrow's plan absorb the ones that still make sense.

Running No Mid-Day Renegotiation Rule for configuring standing assistance

The morning plan and the afternoon rewrite are made by the same person in different states. The afternoon state has more fatigue and less context about why the morning chose what it chose, so its rewrites systematically favor the easier item. Freezing the plan does not make the afternoon smarter; it stops the afternoon from deciding.

The full set of failure modes for this framework, the evidence to record, and a prompt you can paste are on its framework page. This page covers the part specific to configuring standing assistance.

What this is not. It is not rigidity for its own sake. It moves plan changes to a moment when they can be judged, which is not the middle of a hard block.

You are putting something in place that will be there tomorrow without being rebuilt: standing instructions, a stored template, a routine you can invoke by name.

Setup cost: a short configuration session, plus a cold test in a fresh context.

Where it is strong: it applies without you remembering to apply it, which is where most of the value is.

Where it is weak: configuration is invisible once set, so a bad rule keeps operating silently until you go and read it again.
