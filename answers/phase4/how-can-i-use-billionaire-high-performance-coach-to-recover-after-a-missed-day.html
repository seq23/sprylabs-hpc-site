System Drift Recovery Protocol — recover after a missed day (0146)

The day after a miss is spent either doing double or doing nothing, and both outcomes make the day after that harder.

A miss carries no real deadline forward, only guilt, and guilt is answered either by over-correction or by avoidance. Neither is a plan.

Do this first. Log the miss in one line with no explanation, do not schedule any catch-up, and run the normal-size version of the action today at a fixed time.

Do not do this. Doubling up. It makes the return day the hardest day of the week, which attaches a cost to returning.

This level fits when: the situation matches a framework the system already contains. It does not fit when: the situation is genuinely outside the system's scope, which includes anything clinical, legal, financial, or safety-related.

When this framework is the right one. Use it when a system you were running has quietly stopped and you are considering a full rebuild.

  1. List the components of the system as it was, without judging them.
  2. Mark each one running, intermittent, or stopped, using evidence rather than memory.
  3. Restart exactly one stopped component, the one the others depend on most.
  4. Wait a week before restarting a second. Drift usually came from running more components than the week supports.
