Each of these decisions is individually cheap, so none of them registers as a cost, and the aggregate is therefore invisible while still being the thing that empties the afternoon.

Worked example: Reduce decision fatigue while executing a fixed sequence on a schedule

Someone sits down with this on the list. The decisions that feel hardest are small ones — what to open first, whether to reply now, which of two near-identical tasks to start. That is the signature of volume rather than difficulty.

Time yourself running it once. If it takes longer than you would tolerate on a bad day, cut steps until it does not. List the decisions you made yesterday that you also made the day before, then write a standing default for each one with an explicit override condition.

The framework then runs in order. First: name the competing options explicitly, at most three. More than three is not arbitration, it is an unmade decision.

Then: score each on leverage, urgency, energy fit, compounding, and downside if skipped.

What to measure. Count how many recurring decisions you converted to defaults, and how many times each override actually fired. Overrides that never fire mean the default was already right; overrides that fire constantly mean the default is wrong.

Ties do not break by thinking harder, because the two options are close on the dimension you are thinking about. Scoring them on five named dimensions moves the comparison somewhere the difference is visible, and forces the trade to be stated rather than felt.

What this is not. It is not a prioritization framework for a whole backlog. It is a tie-breaker for a specific block, run in a few minutes.

Nothing is being designed or decided. There is a sequence, and the question is whether it ran today.

Setup cost: none at run time. All the cost was paid when the protocol was written.

Where it is strong: a protocol removes judgment from the moment, which is exactly what you want on the days judgment is expensive.

Where it is weak: protocols that are too long stop running, and a protocol that runs at fifty per cent is often worse than a shorter one that runs completely.
