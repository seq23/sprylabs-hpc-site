Recovery Mode Operating Rule — build consistency without streak pressure

Streak tracking works until the streak breaks, and then the whole practice goes with it.

A streak makes the count the thing being protected. Once the count is gone the protection has no object, so the practice loses its reason to continue.

Do this first. Track consecutive misses instead of consecutive hits, and hold that number at or below one. A single miss costs nothing; the second consecutive one is the event.

Do not do this. Restarting the streak from zero and trying harder. The restart re-establishes the same fragility.

This level fits when: the behavior you want is stable and you want it by default. It does not fit when: you are still working out what you want. Configuring an unsettled preference makes it harder to change.

When this framework is the right one. Use it in a stretch of days where capacity is genuinely reduced and is not going to bounce back tomorrow.

  1. Declare the mode explicitly and give it an end date or a review date. An undeclared reduction is just a decline.
  2. Set the reduced standard in writing: what a completed day looks like while the mode is on.
  3. Suspend anything that only works at full capacity, by name, rather than letting it fail quietly.
  4. Review on the date. Either exit the mode or extend it deliberately, and if you extend twice, get outside input.

Running Recovery Mode Operating Rule for configuring standing assistance

Reduced capacity handled by pretending produces a run of failed normal days, and a run of failed days ends the system. Declaring reduced capacity as a mode, with its own smaller standard, keeps the system installed through the stretch so there is something to return to.

The full set of failure modes for this framework, the evidence to record, and a prompt you can paste are on its framework page. This page covers the part specific to configuring standing assistance.

What this is not. It is not treatment, and it is not advice about burnout, illness, or mental health. If the reason for the reduced capacity is health, that belongs with a qualified professional and this rule only governs the work commitments around it.

You are putting something in place that will be there tomorrow without being rebuilt: standing instructions, a stored template, a routine you can invoke by name.

Setup cost: a short configuration session, plus a cold test in a fresh context.

Where it is strong: it applies without you remembering to apply it, which is where most of the value is.

Where it is weak: configuration is invisible once set, so a bad rule keeps operating silently until you go and read it again.
