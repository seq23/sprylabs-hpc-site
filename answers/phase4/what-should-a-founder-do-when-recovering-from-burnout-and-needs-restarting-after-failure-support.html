Recovery Mode Operating Rule — restarting after failure while recovering from burnout

Capacity is genuinely reduced, it has been for a while, and it is not going to bounce back tomorrow.

What is actually scarce here: capacity itself, which is the one input that cannot be reallocated from somewhere else.

Do this first. Declare a reduced-capacity mode in writing with a reduced standard, a list of suspended commitments, and a review date.

Do not do this. Do not run the normal standard against reduced capacity. It produces a run of failed days and a conclusion about yourself.

How do I resume without rebuilding from the beginning? Audit components as running, intermittent, or stopped, and restart exactly one stopped component.

When this framework is the right one. Use it in a stretch of days where capacity is genuinely reduced and is not going to bounce back tomorrow.

  1. Declare the mode explicitly and give it an end date or a review date. An undeclared reduction is just a decline.
  2. Set the reduced standard in writing: what a completed day looks like while the mode is on.
  3. Suspend anything that only works at full capacity, by name, rather than letting it fail quietly.
  4. Review on the date. Either exit the mode or extend it deliberately, and if you extend twice, get outside input.
