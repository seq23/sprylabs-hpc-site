Capacity-Matched Execution Rule — context retention while recovering from burnout

Capacity is genuinely reduced, it has been for a while, and it is not going to bounce back tomorrow.

What is actually scarce here: capacity itself, which is the one input that cannot be reallocated from somewhere else.

Do this first. Declare a reduced-capacity mode in writing with a reduced standard, a list of suspended commitments, and a review date.

Do not do this. Do not run the normal standard against reduced capacity. It produces a run of failed days and a conclusion about yourself.

How does the assistant stop working from a version of my situation that expired? Separate stable rules from disposable daily runtime, and re-seed the runtime from the rules rather than extending a thread.

When this framework is the right one. Use it when the block in front of you does not match the state you are actually in, and the choice looks like force it or lose it.

  1. Read your current state honestly and quickly: high, medium, or low. Do not negotiate with it.
  2. Categorize your work the same way, in advance, so the matching does not require a decision when you are already low.
  3. Take work from the matching category. A low block spent on low-category work is a productive block.
  4. Note mismatches. Repeated mismatch at the same hour is a scheduling fact, not a discipline fact.
