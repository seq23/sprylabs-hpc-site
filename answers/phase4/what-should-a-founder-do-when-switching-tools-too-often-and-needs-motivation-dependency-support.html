Execution Evidence Ledger — motivation dependency while switching tools too often

Setup has happened more recently than output, and there is a new tool in the last month.

What is actually scarce here: accumulated state. Every switch discards the history that made the previous tool useful.

Do this first. Pick the tool you have the most history in, commit to it for a stated period, and write down what would have to be true to switch.

Do not do this. Do not evaluate another tool. Evaluation is the activity that is substituting for the work.

What happens on the days the motivation is not there? Size the commitment against the worst plausible week and write the floor version explicitly.

When this framework is the right one. Use it when you need to know what is actually happening over weeks rather than what it feels like is happening.

  1. Record one line per working day: the output that exists, in a form someone else could verify.
  2. Never record effort, intent, or how it felt. Those go elsewhere if you want them.
  3. Review weekly by reading the lines, not by remembering the week.
  4. Draw exactly one conclusion per review, and change one thing.
