Arbitration Engine — make a hard decision

The decision has been open for weeks. Each time you return to it you rehearse the same considerations and stop in the same place.

Rehearsal is not analysis. The options are close on the dimension you keep thinking about, so thinking about that dimension harder cannot separate them.

Do this first. Score the options on leverage, urgency, energy fit, compounding, and downside if skipped, and name which dimension you are letting decide before you total anything.

Do not do this. Gathering more information. Most of what you would gather does not change the answer, and gathering is a comfortable way to keep the decision open.

This level fits when: you need one answer now and you are not going to do this repeatedly. It does not fit when: you have asked the same kind of question more than three times. At that point the retyping is the cost, and it is worth installing something.

When this framework is the right one. Use it when two or more things genuinely deserve the same block and the tie is not breaking on its own.

  1. Name the competing options explicitly, at most three. More than three is not arbitration, it is an unmade decision.
  2. Score each on leverage, urgency, energy fit, compounding, and downside if skipped.
  3. Say which dimension you are letting decide, before you look at the totals.
  4. Write the losing option's next review date so it is parked rather than abandoned.

Running Arbitration Engine for using a general assistant chat

Ties do not break by thinking harder, because the two options are close on the dimension you are thinking about. Scoring them on five named dimensions moves the comparison somewhere the difference is visible, and forces the trade to be stated rather than felt.

The full set of failure modes for this framework, the evidence to record, and a prompt you can paste are on its framework page. This page covers the part specific to using a general assistant chat.

What this is not. It is not a prioritization framework for a whole backlog. It is a tie-breaker for a specific block, run in a few minutes.

You are working inside an ordinary chat window with no saved setup. Whatever structure exists has to be typed into the message you are about to send.

Setup cost: none. This is the mode you are already in, which is why it is the one people actually use.

Where it is strong: zero friction to start, and it works on any device, any account, any day.

Where it is weak: nothing persists. The quality of the answer is set entirely by what you happened to type this time, so the same question gets a different answer on a different day.
