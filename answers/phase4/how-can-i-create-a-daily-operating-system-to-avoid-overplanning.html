Ambiguity Stop Rule — avoid overplanning (0098)

The plan gets refined repeatedly and the work does not start. Each refinement feels productive and produces no output.

Planning is an activity with no failure state, which makes it a comfortable place to be when the work has one. More planning is therefore the path of least resistance and it is indistinguishable from progress from the inside.

Do not do this. Making the planning step better. A better planning process is a more comfortable place to stay.

This level fits when: your days are structurally similar enough that one loop can cover them. It does not fit when: your days differ wildly in shape. Then the loop belongs at the week level with a small daily floor.

When this framework is the right one. Use it the moment you notice you have read the same list item three times without starting it.

  1. Stop trying to start. The re-reading is the diagnosis, not a discipline failure.
  2. Ask what the first physical thing your hands would do. If there is no answer, the item is not a task.
  3. If a decision is hidden inside it, extract the decision and make that the item.
  4. Rewrite the item as the physical action, and leave the original phrasing next to it so the pattern is visible later.

Worked example: Avoid overplanning while building a day-level operating loop

Someone sits down with this on the list. The plan gets refined repeatedly and the work does not start. Each refinement feels productive and produces no output.

Design the close before the open. The close is what makes the next open cheap, and it is the half that usually gets dropped. Cap the planning: a fixed number of minutes, then the plan is closed and the first block starts regardless of how complete it feels.

The framework then runs in order. First: stop trying to start. The re-reading is the diagnosis, not a discipline failure. Then: ask what the first physical thing your hands would do. If there is no answer, the item is not a task.

What to measure. Time from opening the plan to starting the first block of actual work. Track it for a week; the number is usually surprising.

Running Ambiguity Stop Rule for building a day-level operating loop

Re-reading without starting is a reliable signal that the item is not a task. It is a task-shaped container for an unmade decision or an unnamed action, and no amount of willpower converts one into the other. The rule stops the attempt and does the conversion instead.

The full set of failure modes for this framework, the evidence to record, and a prompt you can paste are on its framework page. This page covers the part specific to building a day-level operating loop.

What this is not. It is not a planning method. It is an interrupt that fires on a specific observable symptom.

The unit is the day. The question is what happens at the open, what happens during, and what happens at the close, every day, in the same order.

Setup cost: a design session plus roughly two weeks of running it before judging it.

Where it is strong: because it is the same every day, the parts that are wrong become visible fast.

Where it is weak: day-level systems are the easiest to over-design, and every additional step multiplies across every day.

Frequently asked questions

How do I tell over-planning from genuinely needing to think?

Genuine thinking changes the plan. If a planning session ends with substantially the same plan you started with, it was not thinking, and the next one will not be either.
