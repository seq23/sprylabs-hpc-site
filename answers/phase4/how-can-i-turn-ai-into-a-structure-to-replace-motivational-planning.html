Operator Discipline Filter — replace motivational planning (0119)

Plans get made in a motivated state and executed in an ordinary one, and the ordinary state cannot carry them.

A plan written while motivated is sized for the motivation. Motivation is not a resource you can schedule, so the plan is effectively sized for conditions that will not reliably recur.

Do this first. Describe your worst plausible week and size the commitment so it still works in that week. Write the floor version explicitly so bad days have an action rather than a decision.

Do not do this. Trying to sustain the motivated state. It is not sustainable, and building on it means rebuilding after every dip.

This level fits when: answers keep coming back plausible and unusable, which is the signature of an unbounded request. It does not fit when: you are exploring and do not yet know what good looks like. Constraints applied to exploration close it early.

When this framework is the right one. Use it when the explanation for a repeated failure has become a statement about your character.

  1. State the failure as an event with a time and a place, not as a trait.
  2. Ask the four structural questions: was it visible, was it scoped, was it scheduled, was it possible at that capacity.
  3. Change the first structural answer that is no, and change only that one.
  4. Observe for a stated period before concluding anything about yourself.

Worked example: Replace motivational planning while converting an open-ended tool into a bounded one

Someone sits down with this on the list. Plans get made in a motivated state and executed in an ordinary one, and the ordinary state cannot carry them.

Write the form constraint first: say exactly what shape the answer must take before you describe the problem. Describe your worst plausible week and size the commitment so it still works in that week. Write the floor version explicitly so bad days have an action rather than a decision.

The framework then runs in order. First: state the failure as an event with a time and a place, not as a trait. Then: ask the four structural questions: was it visible, was it scoped, was it scheduled, was it possible at that capacity.

What to measure. Count the weeks the floor was met. A floor missed more than rarely was set from a good week.

Running Operator Discipline Filter for converting an open-ended tool into a bounded one

Character explanations do not produce fixes, because there is no action that follows from them. Routing the same failure through structural questions produces the fix, and it turns out most repeated failures have a structural cause that was easier to see than to look for.

The full set of failure modes for this framework, the evidence to record, and a prompt you can paste are on its framework page. This page covers the part specific to converting an open-ended tool into a bounded one.

What this is not. It is not psychological assessment and it makes no claim about why anyone behaves as they do. It is four structural questions asked before a character explanation is allowed.

The problem is not capability, it is that the tool will do anything, and anything is a bad default when you are trying to decide one thing.

Setup cost: the work of writing down constraints you have been holding implicitly.

Where it is strong: a bounded tool gives comparable answers across days, which is the precondition for noticing that something changed.

Where it is weak: constraints written too tightly produce answers that are technically compliant and useless.
