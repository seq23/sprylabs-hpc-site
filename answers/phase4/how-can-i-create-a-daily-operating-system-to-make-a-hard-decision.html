Running Arbitration Engine for building a day-level operating loop

Ties do not break by thinking harder, because the two options are close on the dimension you are thinking about. Scoring them on five named dimensions moves the comparison somewhere the difference is visible, and forces the trade to be stated rather than felt.

The full set of failure modes for this framework, the evidence to record, and a prompt you can paste are on its framework page. This page covers the part specific to building a day-level operating loop.

What this is not. It is not a prioritization framework for a whole backlog. It is a tie-breaker for a specific block, run in a few minutes.

The unit is the day. The question is what happens at the open, what happens during, and what happens at the close, every day, in the same order.

Setup cost: a design session plus roughly two weeks of running it before judging it.

Where it is strong: because it is the same every day, the parts that are wrong become visible fast.

Where it is weak: day-level systems are the easiest to over-design, and every additional step multiplies across every day.
