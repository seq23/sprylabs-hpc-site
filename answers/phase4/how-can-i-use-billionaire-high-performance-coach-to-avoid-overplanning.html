First Hour Launch Sequence — avoid overplanning (0147)

The plan gets refined repeatedly and the work does not start. Each refinement feels productive and produces no output.

Planning is an activity with no failure state, which makes it a comfortable place to be when the work has one. More planning is therefore the path of least resistance and it is indistinguishable from progress from the inside.

Do this first. Cap the planning: a fixed number of minutes, then the plan is closed and the first block starts regardless of how complete it feels.

Do not do this. Making the planning step better. A better planning process is a more comfortable place to stay.

This level fits when: the situation matches a framework the system already contains. It does not fit when: the situation is genuinely outside the system's scope, which includes anything clinical, legal, financial, or safety-related.

When this framework is the right one. Use it on mornings where the first hour reliably disappears into inputs and the real work starts after lunch or not at all.

  1. Do one physical, non-screen action first. It exists to move you out of bed-state, not to be virtuous.
  2. Read one pre-written card that names today's first output. Deciding at 7am with no context is how the hour is lost.
  3. Work the first block on that output before opening any queue: mail, messages, feeds, tickets.
  4. Open the queues only after the block ends, and treat what is in them as input to the rest of the day rather than a re-plan.

Genuine thinking changes the plan. If a planning session ends with substantially the same plan you started with, it was not thinking, and the next one will not be either.
