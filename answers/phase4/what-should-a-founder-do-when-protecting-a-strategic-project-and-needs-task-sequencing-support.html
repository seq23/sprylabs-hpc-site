Daily Agenda Engine — task sequencing while protecting a strategic project

There is one project that matters more than the rest and it keeps losing blocks to things that are louder.

What is actually scarce here: uninterrupted time, which is the one input the project needs and the one the day is worst at supplying.

Do this first. Give it the first block of the day and a written rule that it takes every contested block.

Do not do this. Do not rely on intention to protect it. Intention loses to urgency every time, in the moment, reliably.

What order should these go in, given that some unblock others? Sequence by dependency first and use urgency only to break ties within a dependency tier.

When this framework is the right one. Use it at the start of a day where you know roughly what matters but the list has no order and no fit to the hours available.

  1. List fixed constraints first: meetings, travel, care obligations, anything already committed. These are not negotiable inputs.
  2. Subtract them from the waking hours to get the real number of workable hours, then subtract a further margin for transition and overrun.
  3. Fill the remaining hours with named outputs in priority order, stopping when the hours run out rather than when the list runs out.
  4. Everything below the cut goes to the deferred list, in writing, before the day starts.
