First Hour Launch Sequence — build an operator rhythm

Work happens in bursts followed by gaps, and the gaps get longer, so output is unpredictable and hard to plan around.

Burst working is sized to a state rather than to a schedule. Because the state is not repeatable on demand, neither is the output.

Do this first. Fix the shape of the day at three points — the open, one protected block, and the close — and hold those three constant while everything else varies.

Do not do this. Scheduling the whole day. Full scheduling is fragile and breaks on the first real interruption, and once it breaks the rest of the day is improvised.

This level fits when: you need one answer now and you are not going to do this repeatedly. It does not fit when: you have asked the same kind of question more than three times. At that point the retyping is the cost, and it is worth installing something.

When this framework is the right one. Use it on mornings where the first hour reliably disappears into inputs and the real work starts after lunch or not at all.

  1. Do one physical, non-screen action first. It exists to move you out of bed-state, not to be virtuous.
  2. Read one pre-written card that names today's first output. Deciding at 7am with no context is how the hour is lost.
  3. Work the first block on that output before opening any queue: mail, messages, feeds, tickets.
  4. Open the queues only after the block ends, and treat what is in them as input to the rest of the day rather than a re-plan.

Running First Hour Launch Sequence for using a general assistant chat

The first hour sets the day's mode. An hour that begins with other people's requests establishes reactive mode, and reactive mode is hard to leave once the queue is visible. The sequence puts one physical action and one owned block before the inbox so the day starts in the other mode.

The full set of failure modes for this framework, the evidence to record, and a prompt you can paste are on its framework page. This page covers the part specific to using a general assistant chat.

What this is not. It is not a wellness routine and it makes no claim about sleep, exercise, or health. It is an ordering rule for the first sixty minutes.

You are working inside an ordinary chat window with no saved setup. Whatever structure exists has to be typed into the message you are about to send.

Setup cost: none. This is the mode you are already in, which is why it is the one people actually use.

Where it is strong: zero friction to start, and it works on any device, any account, any day.

Where it is weak: nothing persists. The quality of the answer is set entirely by what you happened to type this time, so the same question gets a different answer on a different day.
