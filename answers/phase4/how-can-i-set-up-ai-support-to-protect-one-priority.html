Strategic Patience Filter — protect one priority

Several projects are technically active, all of them get some attention, and none of them has produced a visible result in weeks.

Parallel projects share time in whatever proportion the day's noise dictates, which usually means no project gets a block long enough to reach a result.

Do this first. Name one project foreground for a period measured in weeks, give every other active project a written maintenance floor, and let the foreground take every contested block.

Do not do this. Trying to give each project a fair share. Fairness at the project level produces failure at every project.

This level fits when: the behavior you want is stable and you want it by default. It does not fit when: you are still working out what you want. Configuring an unsettled preference makes it harder to change.

When this framework is the right one. Use it when you are about to change direction and the current direction has not yet run long enough to produce evidence.

  1. Write down what evidence would tell you the current direction is wrong, in advance of looking for it.
  2. Check whether that evidence has actually arrived, or whether what arrived is discomfort.
  3. If the evidence has not arrived, name the date by which it would have, and hold until then.
  4. If it has arrived, pivot deliberately and write down what you learned so the next attempt starts further along.

Worked example: Protect one priority while configuring standing assistance

Someone sits down with this on the list. Several projects are technically active, all of them get some attention, and none of them has produced a visible result in weeks.

Write the standing instruction, then open a completely fresh context and check it behaves the same way. Name one project foreground for a period measured in weeks, give every other active project a written maintenance floor, and let the foreground take every contested block.

The framework then runs in order. First: write down what evidence would tell you the current direction is wrong, in advance of looking for it. Then: check whether that evidence has actually arrived, or whether what arrived is discomfort.

What to measure. At the end of the foreground period, ask whether something exists that did not before. That is the only measure; hours spent is not one.

Running Strategic Patience Filter for configuring standing assistance

Most pivots happen at the point of maximum discomfort, which is usually before the point of maximum information. The filter separates the two by asking what evidence would settle the question and whether it has arrived yet.

The full set of failure modes for this framework, the evidence to record, and a prompt you can paste are on its framework page. This page covers the part specific to configuring standing assistance.

What this is not. It is not a rule against changing direction. It is a rule about when the decision has enough information in it.

You are putting something in place that will be there tomorrow without being rebuilt: standing instructions, a stored template, a routine you can invoke by name.

Setup cost: a short configuration session, plus a cold test in a fresh context.

Where it is strong: it applies without you remembering to apply it, which is where most of the value is.

Where it is weak: configuration is invisible once set, so a bad rule keeps operating silently until you go and read it again.
