Continuity Over Intensity Rule — replace motivational planning (0190)

Plans get made in a motivated state and executed in an ordinary one, and the ordinary state cannot carry them.

A plan written while motivated is sized for the motivation. Motivation is not a resource you can schedule, so the plan is effectively sized for conditions that will not reliably recur.

Do this first. Describe your worst plausible week and size the commitment so it still works in that week. Write the floor version explicitly so bad days have an action rather than a decision.

Do not do this. Trying to sustain the motivated state. It is not sustainable, and building on it means rebuilding after every dip.

This level fits when: you have a design that has survived contact with at least one real day. It does not fit when: you are still redesigning. Installing an unsettled design means reinstalling repeatedly, which is how people conclude systems do not work for them.

When this framework is the right one. Use it when planning a commitment you intend to keep for months, and the version you are about to commit to is the version you could do this week.

  1. Describe your worst plausible week honestly: illness, travel, a crisis at work.
  2. Size the commitment so it is still doable in that week, not in this one.
  3. Write the floor version explicitly, so that on a bad day there is something to do rather than a decision to make.
  4. Let good weeks overflow, but never let the overflow raise the floor.

Running Continuity Over Intensity Rule for putting a system into daily operation

Effort is elastic and schedules are not. A commitment sized to a good week fails in a normal one, and each failure costs more than the extra output of the good week bought. Sizing to the worst plausible week produces a commitment that survives, and surviving is what accumulates.

The full set of failure modes for this framework, the evidence to record, and a prompt you can paste are on its framework page. This page covers the part specific to putting a system into daily operation.

What this is not. It is not an argument against hard work. Intensity is fine; it just cannot be the thing the system depends on.

The design already exists. This is the part where it becomes something that actually runs, which is a different and harder problem than designing it.

Setup cost: low in effort, high in attention: installation fails on details like where the trigger lives.

Where it is strong: installation is where most of the value is realized, and it is the step most often skipped in favor of more design.

Where it is weak: an installed system is hard to see, so a broken component can run broken for weeks.
