Foreground Priority Selection Rule — restarting after failure while scattered across priorities

Several projects are active, each has had some attention this week, and none has produced anything visible.

What is actually scarce here: contiguous blocks. Everything is getting minutes and nothing is getting an hour.

Do this first. Name one foreground project for a stated period and give the others a written maintenance floor.

Do not do this. Do not try to give each project a fair share. Fairness at the project level produces failure at every project.

How do I resume without rebuilding from the beginning? Audit components as running, intermittent, or stopped, and restart exactly one stopped component.

When this framework is the right one. Use it when several projects are all technically active and none of them is visibly moving.

  1. Name one project as foreground for a stated period, measured in weeks rather than days.
  2. Give every other active project an explicit background status with a maintenance floor: the minimum that keeps it from decaying.
  3. When a block is contested, the foreground project takes it. This is the entire rule and its whole value is that it is decided in advance.
  4. Review the foreground choice on a fixed date, not when a background project starts feeling urgent.
