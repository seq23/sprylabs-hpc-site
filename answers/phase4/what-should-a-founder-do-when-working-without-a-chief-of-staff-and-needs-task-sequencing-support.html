Ambiguity Stop Rule — task sequencing while working without a chief of staff

Half-formed obligations arrive faster than they can be converted into actions, and the pile is now the problem.

What is actually scarce here: conversion capacity: the work of turning ambiguity into named actions, which nobody is doing.

Do this first. Run a conversion pass: for each item name the physical next action and the owner, and route anything without one to a decision block.

Do not do this. Do not try to do the pile. It contains items that are not doable because they are not yet tasks.

What order should these go in, given that some unblock others? Sequence by dependency first and use urgency only to break ties within a dependency tier.

When this framework is the right one. Use it the moment you notice you have read the same list item three times without starting it.

  1. Stop trying to start. The re-reading is the diagnosis, not a discipline failure.
  2. Ask what the first physical thing your hands would do. If there is no answer, the item is not a task.
  3. If a decision is hidden inside it, extract the decision and make that the item.
  4. Rewrite the item as the physical action, and leave the original phrasing next to it so the pattern is visible later.
