# BHPC SEO Execution Contract

## Purpose

The Saturday Twin Agent may enrich a run with `seo_execution[]`. This repository treats the raw four-file run folder as immutable evidence, normalizes the structured object, resolves the canonical route owner, compiles visible acceptance requirements, applies only the authorized page changes, and validates the rendered result.

## Supported page decisions

- `repair_existing`
- `build_new`
- `consolidate`
- `no_action`

Existing canonical product, trust, methodology, comparison, and insight routes win before a new route is created.

## Supported page types

Product explanations, pricing or inclusions, comparisons, alternatives, use cases, framework guides, prompt templates, FAQs, privacy/trust, installation guides, and methodology pages are supported. `evaluation_framework` is normalized to a comparison page and `guide` to a framework guide for backward compatibility.

## Commercial claim boundary

The agent may identify a competitor price or feature as evidence, but the repo may not invent Spry/BHPC pricing, competitor capabilities, outcomes, ratings, or endorsements. Live pricing and inclusions must point to the current official purchase page. Schema is generated only from visible content and approved existing schema builders.

## Public-content boundary

Operational phrases such as “Agent recommendation implementation,” “Agent source instruction,” “required acceptance strings,” and “BHPC Agent Acceptance Framework” are not reader-facing content. Record identity and provenance remain in data attributes and validation ledgers.

## Validation

`validate:bhpc-seo-execution` checks the structured contract before implementation. `validate:page-seo` checks rendered titles, H1s, canonicals, JSON-LD parsing, unresolved tokens, public operational scaffolding, exact active record markers, headings, and required internal links. Length and content-depth signals remain warnings unless an exact active contract requires them.

## Compatibility

Legacy runs without `seo_execution` remain valid. `site_health: null` is valid. Monthly site-health data is advisory unless a finding names an exact owned route, a supported action, and an observable acceptance check.
