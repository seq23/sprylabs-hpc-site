Do this first. Put the rules in a file that sits alongside the conversation, and give the file a version marker so a behavior change can be attributed to an edit.

Do not do this. Letting the file grow. A rules document too long to read in full stops being read, and then it stops being the source of truth.

Close the day on evidence rather than on impression. It runs on one trigger: the end of the working day, on good days and bad ones equally.

When this framework is the right one. Use it at the end of any day you plan to draw a conclusion from, especially days that felt bad.

  1. List what is finished, meaning something exists that did not exist this morning.
  2. List what is partial, and for each one write where it stopped so tomorrow starts at the edge rather than the beginning.
  3. List what was missed, without explanations. The explanation is tomorrow's problem, not tonight's.
  4. Write tomorrow's first output as a single sentence and stop.
