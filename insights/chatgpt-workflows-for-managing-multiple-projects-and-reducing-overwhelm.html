Multi-project status review: practical guide

Multi-project status review is a review that exposes deadlines and blocked dependencies across several projects without merging all their tasks into one undifferentiated list.

Quick answer

Write one current outcome, next action and blocker for each active project.

What this guide is best for: readers who need to make a concrete decision about multi-project status review.

How do you put this into practice?

Use the following sequence as a starting plan, then adjust it to the work you are responsible for.

  1. Write one current outcome, next action and blocker for each active project.
  2. Limit new starts when existing projects are waiting for review or handoff you control.
  3. Record the action you chose, its intended result and the next occasion on which you will check it. Keep the record in a place you can return to without rebuilding your setup.

How do you start multi-project status review?

Write one current outcome, next action and blocker for each active project. Use a current commitment rather than a fictional ideal week. Check the actual calendar and inputs before treating the proposed action as feasible.

What should change your plan?

Limit new starts when existing projects are waiting for review or handoff you control. When the conditions change, record the new constraint and choose again. Tell anyone affected by a changed commitment rather than silently moving its deadline.

What mistake should you avoid?

Do not mistake a longer combined task list for a workable cross-project plan. If the method creates more work than it helps you resolve, simplify the record before adding another tool. The plan remains a proposal until you compare it with what actually happened.

What would this look like in practice?

A consultant sees that two projects need approvals and a third needs drafting, then sends the approval requests before choosing the drafting block. This is an illustrative scenario, not a customer result or evidence of a measured improvement.

Frequently asked questions

What should you write down first?

Write one current outcome, next action and blocker for each active project. Keep the first record short enough to use during a real workday. Include the specific deliverable or decision and where the supporting information can be found.

How should you review the result?

Limit new starts when existing projects are waiting for review or handoff you control. Compare the result with the commitment you actually made. Identify one useful change for the next attempt rather than rewriting the entire system after a single difficult day.
