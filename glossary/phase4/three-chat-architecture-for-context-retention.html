When this framework is the right one. Use it when one long assistant thread has become both the rulebook and the daily workspace, and the rules have started drifting.

  1. Create a rules chat that contains only the standing instructions. Never do daily work in it.
  2. Create a runtime chat for today, seeded by pasting the rules block at the top. Discard it when the day ends.
  3. Create a governance chat where proposed rule changes are argued and either accepted into the rules chat or rejected.
  4. Change the rules only in the rules chat, and only from a decision made in the governance chat.

Running Three-Chat Architecture for context retention support

A single thread mixes three incompatible jobs: holding stable rules, running a disposable day, and deciding what the rules should be. The daily traffic pushes the rules out of context, so the rules quietly change without anyone deciding to change them. Splitting the three gives the rules a location that daily volume cannot displace.
