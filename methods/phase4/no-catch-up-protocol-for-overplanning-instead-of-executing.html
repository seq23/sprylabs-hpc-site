When this framework is the right one. Use it when yesterday's undone list is about to be added on top of today's list.

  1. Put yesterday's undone items in a separate place from today's plan. Never merge the two lists.
  2. Give every carried item one of three dispositions: do today as a named block, reschedule to a named day, or drop.
  3. Write the dropped items down as dropped. A deletion you can see is closure; a deletion you cannot see comes back as pressure.
  4. Build today's plan only after the carried list is empty of undecided items.

Running No Catch-Up Closure Rule for a reader who is overplanning instead of executing

Undone work does not carry a deadline forward with it; it carries guilt forward. A carried list makes today structurally impossible, which produces another carried list. The rule forces an explicit disposition for every carried item so that today's list is a list someone could actually finish.

Where it goes wrong

Merging the lists. Today plus yesterday is a list nobody finishes, so the day starts already failed and ends producing another carry-forward. Two lists, one pass, and today's list is written last.

Rescheduling to "this week". An item without a specific day is an item that gets carried again, and the carry count is what generates the guilt. A named day or a drop. There is no third option.

Refusing to drop anything. If nothing can be dropped, the disposition pass is theatre and the list grows monotonically. Expect to drop items. A pass that drops nothing usually means the list is a wish record, not a plan.

Evidence to record. Count carried items at the start of each pass. A working rule drives that number down over a week rather than flat or up.

A line you can paste. Here is yesterday's undone list. Ask me to assign each item do-today, reschedule-to-a-named-day, or drop. Do not let me leave one undecided.

What this is not. It is not a productivity trick for getting more done. It usually results in less being done and more being finished.
